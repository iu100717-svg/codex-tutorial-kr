## 목표

비밀번호나 API 키를 실수로 공개 저장소에 올리는 상황을 피할 수 있다.

## 왜 위험한가

[GitHub Pages로 배포하기](/build/06-deploy/)에서처럼 저장소를 Public으로 만들면, 그 안의 모든 파일을 누구나 볼 수 있다. 비밀번호나 API 키가 코드 파일 안에 그대로 적혀 있으면, 저장소를 Public으로 올리는 순간 전 세계에 공개된다.

이 사이트에서 만드는 정적 포트폴리오 페이지는 API 키가 필요 없지만, 앞으로 로그인 기능이나 외부 서비스 연동이 있는 프로젝트를 만들 때는 반드시 주의해야 한다.

## 절대 하지 말아야 할 것

- 비밀번호, API 키를 코드 파일 안에 직접 적어넣고 그 파일을 Public 저장소에 올리는 것
- Codex와의 대화 중에 실제 비밀번호나 API 키를 그대로 붙여넣는 것

## 만약 실수로 올렸다면

- 해당 비밀번호나 API 키를 즉시 재발급(변경)한다. 저장소에서 파일만 지운다고 이미 공개된 적 있는 값이 안전해지지 않는다
- 어느 서비스의 키였는지에 따라 재발급 방법이 다르므로, 해당 서비스의 계정 설정에서 확인한다

## Codex에게 도움을 받을 때 주의할 점

민감한 값을 다뤄야 하는 상황이라면, 실제 값 대신 "여기에 API 키를 넣는 자리를 만들어줘"처럼 자리만 만들어달라고 요청한다. 실제 값은 직접 입력하고, 대화 내용에는 남기지 않는다.
