## 목표

Codex의 답이 항상 맞지는 않다는 것을 알고, 직접 확인하는 습관을 들인다.

## 무슨 일이 생기는가

Codex는 틀린 답을 내놓을 때도 망설이는 말투를 쓰지 않는다. 맞는 답을 말할 때와 똑같이 확신에 찬 말투로 틀린 내용을 말할 수 있다. 이런 현상을 흔히 [할루시네이션](/reference/glossary/#할루시네이션)이라고 부른다.

코드에서는 다음과 같은 형태로 나타날 수 있다.

- 존재하지 않는 함수나 기능을 있는 것처럼 쓰는 것
- 실제로 실행해보지 않고 "이제 잘 동작합니다"라고 말하는 것
- 존재하지 않는 URL이나 파일 경로를 사실인 것처럼 제시하는 것

## 왜 위험한가

말투가 확신에 차 있기 때문에, 특히 코딩을 처음 배우는 입장에서는 틀렸다는 것을 스스로 알아채기 어렵다. "Codex가 그렇게 말했으니 맞겠지"라고 그냥 넘어가면, 나중에 [에러가 났을 때](/build/05-debug/) 원인을 찾기 더 어려워진다.

## 확인하는 습관

- 결과를 눈으로 직접 본다. [실행해서 눈으로 보기](/build/03-preview/)처럼 "이렇게 나오면 성공"을 직접 확인하기 전에는 완료됐다고 믿지 않는다
- Codex가 만든 URL이나 파일 경로가 진짜 있는지 클릭하거나 열어서 확인한다
- 의심스러운 답이 나오면 "정말 그래? 어떻게 확인했어?"라고 되물어본다
