## 목표

만든 코드를 Codex에게 검토받아, 스스로는 찾기 어려운 문제를 발견할 수 있다.

## 사전 조건

- [ ] [완성 점검](/build/07-checklist/)까지 완료했다

## 왜 리뷰를 따로 요청하는가

[뼈대 만들기](/build/02-scaffold/)나 [고치고 다시 시키기](/build/04-iterate/)에서는 "만들어줘", "고쳐줘"처럼 결과물을 요청했다. 리뷰는 반대로, 이미 있는 코드를 검토해서 문제점을 찾아달라고 요청하는 것이다. 목적이 다르면 같은 코드를 봐도 다른 문제가 보인다.

## 요청 예시

```
지금까지 만든 index.html, style.css, script.js 파일을 검토해줘.

확인해줬으면 하는 것:
- 접근성(스크린 리더 등으로 봐도 문제없는지)에 문제가 없는지
- 같은 코드가 불필요하게 반복되는 부분이 있는지
- 화면 크기가 작을 때 깨지는 부분이 있는지

문제를 찾으면 왜 문제인지도 설명해줘.
```

## 리뷰 결과를 다루는 법

리뷰에서 나온 지적을 전부 그대로 받아들일 필요는 없다. 왜 문제라고 판단했는지 이해가 안 되면 "왜 그게 문제야?"라고 되물어본다. 이해한 것만 반영한다.
